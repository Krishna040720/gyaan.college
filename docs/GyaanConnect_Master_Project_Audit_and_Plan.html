1. Current Architecture Overview

The platform is structured as a client-centric single-page application paired with a lightweight Node.js API service:

  • Frontend Layer: React 19 (^19.2.8), Vite 8 (^8.2.2), Tailwind CSS v4 (^4.3.3), Lucide icons, and Canvas Confetti.
  • Backend Layer: Native Node.js ESM HTTP service (server/index.js) on port 3001, reverse-proxied in development via Vite (/api → http://localhost:3001).
  • 3-Tier AI Evaluation Pipeline:
    • Tier 1 (Server Proxy): POST /api/evaluate calls Google Gemini API with server-side credentials.
    • Tier 2 (Client Fallback): Optional client key entered in modal (stored in localStorage; marked for removal).
    • Tier 3 (Local Socratic Engine): 100% offline, zero-cost heuristic evaluator matching must-know points and detecting misconceptions.
  • Pedagogical DAG Engine: Directed Acyclic Graph dependency model (conceptGraphEngine.js) mapping ancestral prerequisites and diagnosing foundational learning gaps.
  • Spaced Repetition Scheduler: Implementation of the SuperMemo SM-2 algorithm scheduling review sessions at 1-day, 3-day, and 7-day intervals based on student accuracy.
  • Native Audio Synthesis: Web Audio API oscillators producing zero-latency auditory feedback for clicks, success chords, and error tones without external MP3 dependencies.

3. Confirmed Errors & Missing Features

🚨 Linter Failure: npm run lint Exits with Code 1

Root Cause: vite.config.js defines cacheDir: './.vite_cache', but .oxlintrc.json and .gitignore do not exclude .vite_cache. Oxlint scans pre-bundled vendor dependencies (lucide-react.js), failing with 3,186 warnings and 14 errors.

Targeted command: npx oxlint src server succeeds with 0 errors and 2 minor effect warnings.

⚠️ Missing Backend Routes: HTTP 404 on Curriculum API Calls

curriculumService.js queries GET /api/curriculum/subjects and GET /api/curriculum/chapters, but neither endpoint exists in server/index.js. The server returns 404, which the client silently catches and falls back to local data.

⚠️ Conflicting Board Definitions & Procedural Chapter Fabrication

Data Fragmentation: conceptKnowledgeBase.js defines 9 boards, curriculumDatabase.js defines 5 boards, and curriculumData.js defines only 3 boards. Selecting Maharashtra, Rajasthan, or Bihar causes getGradeData() to default back to UP Board.

Mock Masquerading: Only Class 10 Science & Math have authentic syllabi. For all other grades (Classes 1–9, 11, 12), generateChaptersForSubject() synthesizes dummy titles ("Chapter 1: Mathematics - Unit 1") and generic quizzes.

ℹ️ Dead / Orphaned Code

src/components/AiVoiceRoom.jsx (584 lines, 24.8 KB) is completely unreferenced and superseded by ProveUnderstandingStudio.jsx.

Missing Features Against Master Project Requirements:

  • Materials & Practical Instructions: No structured lab apparatus list, safety guidelines, or step-by-step experiment instructions.
  • Real-World Examples & News Links: No connection of curriculum concepts to contemporary science news (e.g. ISRO missions).
  • Server-Side Progress Persistence: No user database; all data is strictly in browser localStorage.
  • Automated Testing: Zero unit, integration, or end-to-end tests exist in the project.

4. Security & Privacy Audit

🚨 Critical: Insecure Evaluation Rubric Injection (Prompt Tampering)

In server/index.js (lines 38–60), the backend blindly constructs the evaluation prompt using concept.mustKnowPoints provided in the client's HTTP request body:

Must-Know Core Points: ${JSON.stringify(targetConcept.mustKnowPoints || [])}

A student or malicious script can send arbitrary mustKnowPoints matching their exact words to score 100%. The server must look up trusted rubrics from curriculumDatabase.js using conceptId.

⚠️ Client-Side API Key Storage & Direct Gemini Calls

GeminiSettingsModal.jsx saves Gemini API keys to localStorage, and aiVoiceService.js directly initiates raw browser fetch requests to Google's API endpoint. This risks credential exposure to browser extensions and shared school PCs.

✅ Child Privacy & Audio Retention Compliance

Audio is never recorded, retained, or transmitted to third-party cloud servers. Speech recognition occurs entirely in browser memory through the native Web Speech API.
